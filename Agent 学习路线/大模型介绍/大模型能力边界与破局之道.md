## 局限一：幻觉问题（Hallucination）

**这是大模型最广为人知的问题，也是最危险的问题。大模型有时候会一本正经地编造根本不存在的事实。它不会坦然说"我不知道"，而是会用流畅的语言、自信的语气说出看起来很像那么回事、但完全是假的内容。**

#### 为什么会有幻觉？
大模型的核心任务是“预测下一个最有可能出现的词”

它不是在知识库里查找答案，而是根据语言模式生成"看起来合理"的内容。它不知道自己说的对不对，只知道这样说"读起来很通顺"。

具体来说：
1. 训练目标不是正确，而是流畅
2. 模型内部没有知识库，也没有办法验证自己说的是否正确
3. 大模型被训练成要给出完整，有帮助的答案，宁编不缺
4. 语言模式的误导，如果训练数据中的某种模式频繁出现，模型可能在不适用的场景也套用

#### 应对策略
1. 在prompt中明确告诉模型：不确定答案的时候，明确说出不知道
2. 要求提供来源
3. 适用 RAG 技术：把相关的参考资料通过检索系统找出来，放在prompt里，让模型基于这些资料回答。
4. 人工审核
5. 交叉验证

## 局限二：精确计算是短板

大模型本身不擅长数学计算：对于数字的处理，大模型在处理时会将其切成Token，数字也会被切分，**模型看到的是 Token的组合，而不是数字本身，它不是在做数学运算，而是在做语言模型匹配**

大模型内部并没有计算器，当执行数学运算的时候，它只是在猜测一个看起来合理的答案

#### 解决方案

1. 最佳方案让模型调用计算工具：这就是Function call / Tool Use技术的用武之地
2. 让模型生成代码来计算
3. 通过CoT(思维链)让模型分布计算，可以减少计算错误


## 知识有边界
大模型的知识来自训练数据，训练数据没有的内容，就不知道

**时间边界：知识截止日期**

每个模型都有一个训练数据截止日期，这个日期之后发生的事情，模型并不知道

**范围边界：私有信息不可见**

#### 知识边界的解决方案

**RAG（检索增强）**

这是解决知识边界问题的主流方案：
```
用户提问
    ↓
从私有知识库检索相关文档片段
    ↓
把片段 + 问题一起发给大模型
    ↓
模型基于片段生成回答
```

**知识库定期更新**

**联网搜索**

**模型微调**

把领域知识“植入”模型，让它内化这些知识，但成本较高，且知识的更新不灵活


## 局限四：没有实时性

大模型的知识是静态的，训练完成后即定格，在开启联网功能后，它在回答问题之前会去搜索引擎搜索一下，把搜索结果喂给模型，**本质上还是 RAG的思路，只不过检索源头是互联网而不是私有知识库**

#### 解决方案
1. **搜索增强**：让模型调用搜索引擎 API，获得最新的网页内容
2. **API 工具调用**：让模型调用各种实时数据的 API

#### 技术二：RAG （检索增强生成）

是解决知识边界和幻觉的核心技术

RAG = retrieval-augmented generation

不指望模型什么都知道，而是在需要的时候喂给相关资料

```
用户提问："我们公司的年假政策是什么？"
    ↓
【检索阶段】
从公司知识库中搜索"年假政策"相关的文档
    ↓
找到《员工手册》第 5 章"休假制度"相关段落
    ↓
【增强阶段】
构建 Prompt：
"根据以下公司资料回答员工的问题：

【参考资料】
员工入职满一年可享受 5 天年假，每增加一年工龄增加 1 天，
上限为 15 天。年假需提前 3 个工作日申请...

【问题】
我们公司的年假政策是什么？"
    ↓
【生成阶段】
大模型基于提供的资料生成回答
    ↓
回答："根据公司规定，员工入职满一年后可享受 5 天年假..."
```

#### 技术三：Agent架构

Agent是把各种技术组合起来，让大模型能够自主的完成复杂任务架构

智能体是一个自主感知环境、做出决策、执行行动的系统

在大模型的语境下，Agent通常以大模型为大脑，配合各种工具和记忆系统，能够自主完成复杂任务的应用

**Agent的核心能力**

1. 任务规划：把复杂任务划分成可执行的步骤
2. 工具调用：选择合适的工具执行每个步骤
3. 执行和观察：执行工具调用，观察结果，根据结果决定下一步
4. 记忆
5. 反思和修正

#### 技术五：模型微调

微调是在基础模型上进行额外的训练，让模型更适合特定任务

具体是用特定领域或任务数据，在已经训练好的基础模型上继续训练，让模型学会新的知识和能力

##### 微调的类型
1. 全参数微调：对模型的所有参数都进行训练。效果最好，但成本最高
2. LoRA/QLoRA：指训练一小部分参数，效果接近全参数微调，成本大幅降低
3. Prompt tuning：只训练一组可学习的提示词向量，模型参数不变，成本最低，但效果有限

##### 什么时候需要模型微调
1. 特定领域的深度应用
2. 需要特定的输出格式或风格
3. Prompt工程和RAG效果不够
4. 需要内化大量领域知识

##### 不需要微调的场景
1. 知识可以通过 RAG 注入
2. 没有高质量的训练数据
3. 预算有限
