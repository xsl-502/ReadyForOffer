# Token

采用*字词分词*，把不常见的词拆成更小的单位，采用 BPE 算法（Byte pair encoding 字节对编码）

* 高频词保持完整
* 低频词被拆分
* 新词也能处理（组合已有的字词）*


# 上下文窗口

*包括了输入和输出的总和*

大模型本身没有记忆，每次 API 调用都是独立的，所谓的“多轮对话”，是在每次请求时把之前的对话历史都带上。

#### 超出上下文窗口怎么办？

* 截断历史消息
* Map-Reduce：把长文段分成许多块，每块单独处理，最后汇总结果
* 滑动窗口+摘要：对早期信息摘要+最近消息
* 选择更大上下文模型*

#### 关键信息
* 上下文越长则模型的表现可能越差
* 不要因为有大上下文就一股脑塞满。精选最相关的内容，控制在合理的长度
* 把重要的信息放在开头或结尾
* 如果必须提供很长的上下文，则可以在最后重复强调关键点*

# Temperature：控制回答的“创意度”

标准的Softmax函数:(exp为自然指数函数)
$$P(wi) = exp(zi) / Σexp(zj)$$

带有Temperature的 softmax：
$$P(wi) = exp(zi/T) / Σexp(zj/T)$$
是一个控制大模型输出随机性的参数，取值范围是 0～2 不等，大模型生成文本是计算选词的概率，然后选择一个词输出：

* 0：总是选择概率最高的词，输出最确定，最保守
* 1：按照原始概率分布采样，比较均衡
* >1：放大低概率词的机会，输出更加随机，更疯狂*

# MoE ：让大模型又大有便宜

#### 什么是MoE
MoE（Mixture of Experts，混合专家） 是一种模型架构，核心思想是：不是每次推理都使用全部参数，而是动态选择部分"专家"来处理当前输入。

#### MoE的工作原理

核心组件如下：
1. 多个专家（Experts)：每个专家是一个独立的小型神经网络（通常为前馈网络 FFN）
2. 门控网络（Router/Gating Network)：决定当前输入应该使用哪些专家

```
输入 Token
    ↓
门控网络（Router）分析输入
    ↓
选择 Top-K 个最相关的专家（通常 K=2）
    ↓
只激活被选中的专家进行计算
    ↓
合并专家的输出
    ↓
输出结果
```

#### MoE的关键指标
1. 总参数：所有专家加起来的参数量
2. 激活参数：每次推理实际使用的参数量

![[截屏2026-09-20 10.54.05.png|342]]

##### 优势 1：性价比高
用较少的计算量来获得大模型的效果
DeepSeek-V3：
1. 总参数量大 671B 的知识容量，学得多，知道的多
2. 实际推理成本约等于 37B 的模型，跑得快，成本少

这就为什么DeepSeek的api价格可以比 GPT4 便宜 10-20 倍

##### 优势二：可扩展性强

传统模型要变大，计算容量会等比例增加。参数翻倍，计算量也翻倍

MoE 可以只增加专家数量，而保持每次激活的专家数量不变。从 8 个专家增加到 256 个，但每次还是只激活 8 个，计算量基本不变。

理论上可以扩展到任意大的参数量，而计算成本增长有限。

##### 优势三：专家专精

进行专业分工

##### 局限一：显存占比依然很大

虽然每次都激活部分专家，但是所有的专家参数都要加载到显存中。

DeepSeek-V3 激活参数只有 37B，但部署时需要加载全部 671B 参数。

对于本地部署来说，MoE的模型的显存需求比同等激活参数的普通模型大得多

##### 局限二：负载均衡问题
如果门控网络总是把输入路由到少数几个专家，其他专家就被"冷落"了，造成：

热门专家过载，成为瓶颈
冷门专家参数浪费
训练不均衡
需要专门的损失函数（如负载均衡损失）来约束，让专家之间的负载尽量均匀。

##### 局限三：训练复杂度高
MoE 模型的训练比普通模型更复杂：

需要处理专家负载均衡
分布式训练时的通信开销更大
调参空间更大（专家数、激活数、路由策略……）

# 深度思考与CoT：让模型想清楚再说

### CoT（思维链）的本质
CoT（Chain of Thought，思维链） 是实现深度思考的一种技术。核心思想是：让模型像人一样，一步一步地推理，把中间过程写出来，而不是直接跳到答案。

为什么这样有效？

想象你做一道复杂的数学题。如果直接心算，很容易出错。但如果在草稿纸上一步步写出来，每一步都是简单的计算，最后把结果串起来，正确率就高很多。

大模型也是一样。直接生成最终答案，中间的推理是"隐式"的，容易出错。把推理过程"显式"地写出来，相当于强迫模型一步一步想清楚。

# 模型量化
**量化（Quantization）是一种模型压缩技术，通过降低参数的数值精度来减少模型的大小和计算量。**

大模型的参数通常是 32 位浮点数（FP32）或 16 位浮点数（FP16/BF16）。每个参数用 2-4 个字节存储。

量化就是把这些参数转换成更低精度的表示，比如 8 位整数（INT8）、4 位整数（INT4），甚至 2 位（INT2）。

好处：
1. 显存占用减少
2. 推理速度提升
3. 部署成本降低

##### 常见的量化方法
###### PTQ（Post-Training Quantization）训练后量化
在模型训练后进行量化，不需要重新训练

代表方法：
1. GPTQ：分析权重分布，选择最优的量化策略
2. AWQ：考虑激活值的分布，保护重要权重
3. GGUF：llama.cpp项目推广的格式

###### QAT（Quantization-Aware Training）量化感知训练
在训练过程中就考虑量化，让模型"学会"适应低精度表示。效果通常比 PTQ 更好，但需要重新训练。


## 量化格式详解

**GPTQ**

* 需要GPU 运行
* 量化过程需要校准数据集
* 精度损失较小
* 社区支持好*

**AWQ**
* 需要GPU 运行
* 考虑激活值的分布，保护对输出影响大的权重
* 量化质量可能比GPTQ更好*

**GGUF**
* 支持 cpu 运行，无需显卡
* 由llam.cpp项目推广
* 支持多种量化级别
