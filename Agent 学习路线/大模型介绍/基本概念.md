# Token

采用*字词分词*，把不常见的词拆成更小的单位，采用 BPE 算法（Byte pair encoding 字节对编码）

* 高频词保持完整
* 低频词被拆分
* 新词也能处理（组合已有的字词）*


# 上下文窗口

*包括了输入和输出的总和*

大模型本身没有记忆，每次 API 调用都是独立的，所谓的“多轮对话”，是在每次请求时把之前的对话历史都带上。

#### 超出上下文窗口怎么办？

* 截断历史消息
* Map-Reduce：把长文段分成许多块，每块单独处理，最后汇总结果
* 滑动窗口+摘要：对早期信息摘要+最近消息
* 选择更大上下文模型*

#### 关键信息
* 上下文越长则模型的表现可能越差
* 不要因为有大上下文就一股脑塞满。精选最相关的内容，控制在合理的长度
* 把重要的信息放在开头或结尾
* 如果必须提供很长的上下文，则可以在最后重复强调关键点*

# Temperature：控制回答的“创意度”

是一个控制大模型输出随机性的参数，取值范围是 0～2 不等，大模型生成文本是计算选词的概率，然后选择一个词输出：

* 0：总是选择概率最高的词，输出最确定，最保守
* 1：按照原始概率分布采样，比较均衡
* >1：放大低概率词的机会，输出更加随机，更疯狂*
