# 大模型 API 调用实战学习计划

## 1. 学习目标

本项目的目标是通过实际编码，掌握大模型 API 调用的完整基础流程。完成后，你应该能够：

- 理解大模型 API 的请求、响应、模型、Token 和上下文等基本概念。
- 使用 Python 调用大模型 API，并正确读取返回结果。
- 安全地管理 API Key，不把密钥直接写入代码或提交到 Git。
- 使用多轮对话、流式输出和结构化输出。
- 处理超时、限流、网络异常和无效响应。
- 记录 Token 用量、请求耗时和调用成本。
- 独立完成一个可运行的命令行大模型应用。

## 2. 技术路线

本项目优先使用以下技术：

- 编程语言：Python 3.11 或更高版本
- 环境管理：Python `venv`
- 配置管理：`.env` 和环境变量
- HTTP/API 调用：官方 Python SDK 为主，`httpx` 或 `requests` 为辅
- 数据校验：Pydantic
- 测试：pytest
- 版本管理：Git

前期建议选择一个提供 OpenAI 兼容接口的模型服务商。这样可以先掌握统一的调用方式，后续再迁移到其他厂商。

## 3. 学习阶段

### 阶段一：准备开发环境

目标：建立一个隔离、安全、可重复运行的 Python 项目环境。

动手任务：

1. 检查 Python 和 Git 是否安装。
2. 创建并激活虚拟环境 `.venv`。
3. 创建依赖文件 `requirements.txt` 或 `pyproject.toml`。
4. 安装模型 SDK、`python-dotenv`、Pydantic 和 pytest。
5. 创建 `.env.example`、`.gitignore` 和基础项目目录。
6. 注册模型服务，获取 API Key，并将其只保存在本机 `.env` 中。

验收标准：

- 能在虚拟环境中运行 Python。
- 代码可以读取环境变量中的 API Key。
- `git status` 不会显示 `.env` 文件。

### 阶段二：完成第一次 API 调用

目标：发送一个最小请求并打印模型回答。

动手任务：

1. 初始化 API 客户端。
2. 指定模型名称。
3. 发送一条简单用户消息。
4. 从响应对象中提取文本。
5. 打印模型名称、回答内容、请求耗时和 Token 用量。

建议练习：

- 让模型用三句话解释什么是 API。
- 修改提示词，观察回答变化。
- 修改温度等生成参数，比较输出差异。

验收标准：

- 命令行能够稳定打印模型回复。
- API Key 不出现在源代码和终端日志中。
- 能解释请求中每个主要参数的作用。

### 阶段三：理解消息与多轮对话

目标：掌握 system、user、assistant 消息及上下文管理。

动手任务：

1. 设置系统提示词，规定模型角色和回答风格。
2. 保存每轮用户问题和模型回复。
3. 将历史消息随下一次请求一起发送。
4. 支持在命令行连续对话。
5. 添加 `exit` 和 `clear` 命令。

验收标准：

- 模型能够记住同一次会话中的前文。
- 清空历史后，模型不再依赖之前的对话。
- 能说明上下文变长为什么会增加 Token 消耗。

### 阶段四：实现流式输出

目标：让模型生成的内容像聊天应用一样逐步显示。

动手任务：

1. 开启流式响应。
2. 逐块读取增量内容。
3. 在同一行实时打印内容。
4. 正确处理流结束、空数据和中途异常。
5. 比较普通调用与流式调用的首字响应时间。

验收标准：

- 回答能够边生成边显示。
- 输出过程中没有重复文本或异常换行。
- 网络中断时程序能给出清晰错误提示。

### 阶段五：结构化输出

目标：让模型返回程序可以可靠处理的数据，而不只是自然语言。

动手任务：

1. 定义一个 Pydantic 数据模型。
2. 要求模型返回符合约束的 JSON 数据。
3. 将响应解析为 Python 对象。
4. 对缺少字段、字段类型错误等情况进行处理。
5. 保存一份结构化结果到本地 JSON 文件。

建议练习：

- 输入一段招聘信息，提取岗位、技能、经验要求和地点。
- 输入一段文章，提取标题、摘要、关键词和情感倾向。

验收标准：

- 正常响应可以通过数据模型校验。
- 非法响应不会导致程序无提示崩溃。
- 能说明结构化输出适合哪些业务场景。

### 阶段六：错误处理与稳定性

目标：让程序面对常见 API 故障时仍然可控。

动手任务：

1. 区分认证失败、参数错误、限流、超时和服务端错误。
2. 为可重试错误实现指数退避重试。
3. 设置连接超时和响应超时。
4. 添加日志，但对 API Key 等敏感信息进行脱敏。
5. 为 API 调用封装统一的客户端函数或类。

验收标准：

- 故意使用错误配置时，提示信息明确。
- 临时网络错误可自动重试，且重试次数有上限。
- 日志中不存在完整 API Key。

### 阶段七：成本、性能与测试

目标：理解真实应用中的调用成本，并验证核心逻辑。

动手任务：

1. 统计输入 Token、输出 Token 和总 Token。
2. 记录每次请求的总耗时。
3. 根据模型价格估算单次调用成本。
4. 使用 Mock 编写不消耗真实 API 额度的单元测试。
5. 编写一个可选的真实 API 集成测试。

验收标准：

- 每次调用后都能看到用量和耗时。
- 自动化测试不会默认调用真实付费 API。
- 核心响应解析与异常处理逻辑有测试覆盖。

### 阶段八：完成综合实战项目

目标：完成一个命令行“文本分析助手”。

功能要求：

1. 用户可以直接输入文本，或指定本地 `.txt` 文件。
2. 用户可以选择摘要、关键词提取或信息结构化模式。
3. 普通文本回答支持流式输出。
4. 信息提取结果保存为 JSON。
5. 程序展示请求耗时和 Token 使用量。
6. API 异常时给出可理解的提示。
7. 项目 README 包含安装、配置和运行说明。

最终验收：

- 新环境按照 README 能独立安装和运行。
- 至少准备 3 个输入示例并得到正确结果。
- API Key 未进入 Git 历史。
- 核心功能有自动化测试。

## 5. 建议学习安排

建议用 7 天完成第一轮，每天约 1 至 2 小时：

| 天数 | 学习内容 | 当日产出 |
| --- | --- | --- |
| 第 1 天 | 环境配置与 API 基础 | 可安全读取 API Key 的项目环境 |
| 第 2 天 | 第一次 API 调用 | `basic_call.py` |
| 第 3 天 | 多轮对话与流式输出 | `streaming_chat.py` |
| 第 4 天 | 结构化输出 | `structured_output.py` |
| 第 5 天 | 异常、重试与日志 | 稳定的 API 客户端封装 |
| 第 6 天 | Token、成本与测试 | 用量统计和测试用例 |
| 第 7 天 | 综合项目与文档 | 可运行的文本分析助手 |

## 6. 学习原则

- 每学一个概念，立即写一个最小可运行示例。
- 每次只增加一个新能力，保证修改前后的代码都能运行。
- 遇到报错先阅读状态码和错误信息，再修改代码。
- 不要把 API Key 发给他人、写进代码、截图或提交到仓库。
- 对真实 API 调用设置额度或预算提醒，避免意外费用。
- 保留实验记录，写下参数、输入、输出和自己的观察。

## 7. 下一步

按照本计划，下一步应完成“阶段一：准备开发环境”，包括初始化 Python 项目、虚拟环境、依赖、环境变量模板和 Git 忽略规则。完成环境检查后，再选择具体模型服务商并实现第一次 API 调用。
